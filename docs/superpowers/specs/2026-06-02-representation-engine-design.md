# ClassicalLieAlgebra — Phase 2 design: the representation engine

**Date:** 2026-06-02
**Status:** Draft for review
**Scope:** Add a high-level irreducible-representation layer to the Phase 1 paclet: `Irrep[g, highestWeight]` plus accessor functions for dimension, weight system, Casimir eigenvalue, and the explicit generator matrices in the irrep — for **all** classical types A/B/C/D, including spinor representations, in exact arithmetic.

## 1. Goals & non-goals

**Goals**
1. `Irrep[g, λ]` — an irrep object for a classical algebra `g` and dominant highest weight `λ` (Dynkin labels).
2. Combinatorial data, exact, all types: `RepresentationDimension`, `WeightSystem` (weights + multiplicities), `CasimirEigenvalue`.
3. Explicit generator matrices in the irrep via a **uniform abstract highest-weight / Shapovalov-form construction** that reaches every irrep including so/sp spinors: `RepresentationMatrices`.
4. Validate against known values, internal consistency (`[E_i,F_j]=δ_ij H_i`), the Phase-1 defining rep, and an external oracle (GroupMath).

**Non-goals (later / out of scope):** tensor-product decomposition and branching rules; Gelfand–Tsetlin closed-form fast paths; exceptional algebras; a tableau/tensor matrix engine (the abstract engine supersedes it; Phase-1 tableau code remains an optional su(n) cross-check only).

## 2. Public API (separate accessor functions)

`Irrep[g, λ]` is an **inert object** (like `LieAlgebra[…]`): `g` a classical algebra (canonical or `SU/SO/Sp` sugar), `λ` a list of `Rank[g]` **non-negative integers** (Dynkin labels). It validates and stays inert; accessors compute (and memoize) on demand.

| Function | Returns |
| :--- | :--- |
| `Irrep[g, λ]` | the inert irrep object (validates `λ`) |
| `HighestWeight[ir]` | `λ` (Dynkin labels) |
| `RepresentationDimension[ir]` | the dimension (integer, Weyl formula) |
| `WeightSystem[ir]` | `<|weight → multiplicity, …|>`, weights as Dynkin-label vectors |
| `CasimirEigenvalue[ir]` | quadratic Casimir eigenvalue (exact) |
| `RepresentationMatrices[ir]` | `<|"Cartan"→{Hᵢ}, "Raising"→{Eᵢ}, "Lowering"→{Fᵢ}|>` — the Chevalley generators of `g` in the irrep (one per simple root), matching the `Generators[g,"Chevalley"]` association shape |

- Each accessor takes an `Irrep[g, λ]` object as its argument.
- `RepresentationMatrices` default: the **orthonormal** basis (so `Eᵢ = ConjugateTranspose[Fᵢ]`, `Hᵢ` real-diagonal; entries are exact algebraic numbers, square roots of rationals). Option `"Normalized" → False` returns the exact **rational** unnormalized basis (then `Eᵢ ≠ Fᵢ^†`, adjoint instead w.r.t. a diagonal rational metric).
- Validation: wrong-length `λ`, or any negative/non-integer label → `Message` + `$Failed`.
- Display: `MakeBoxes` shows e.g. `Irrep(𝔤, λ)` compactly (dimension in a tooltip is optional).
- Symbol-collision check (as in Phase 1): verify `Irrep`, `HighestWeight`, `RepresentationDimension`, `WeightSystem`, `CasimirEigenvalue`, `RepresentationMatrices` are not `System`` symbols; rename any clash.

## 3. Conventions

- **Internal coordinates:** weights in the **Euclidean basis** (Phase 1 supplies `SimpleRoots`, `PositiveRoots`, `FundamentalWeights` there), inner product = plain `Dot`. Convert a Dynkin-label weight `a` to Euclidean by `Σ aᵢ ωᵢ`; convert back via `⟨μ, αᵢ^∨⟩ = 2(μ,αᵢ)/(αᵢ,αᵢ)`. Public input/output uses **Dynkin labels**.
- `ρ = Total[FundamentalWeights[g]]` (= half-sum of positive roots).
- **Normalization:** long-root² = 2 (Bourbaki/Humphreys). Dimension and multiplicities are **scale-invariant**, so raw Euclidean `Dot` is correct for all types. The **Casimir is not scale-invariant**: for `C_n` the raw coords give long-root² = 4, so `CasimirEigenvalue` halves the form on `C_n` (documented), giving `C₂(adjoint) = 2 h^∨` uniformly.
- **Exactness:** all arithmetic exact (rationals; half-integers for B/D spinor weights; `Sqrt` surds only from orthonormalization).

## 4. Layer 1 — combinatorial (`Kernel/Weights.wl`)

- **Dimension:** `RepresentationDimension = Times @@ ((λ+ρ).α / ρ.α  for α in PositiveRoots)` (exact; resolves to an integer).
- **Weight multiplicities (Freudenthal):** for dominant `λ` and weight `μ`,
  `(‖λ+ρ‖² − ‖μ+ρ‖²) m(μ) = 2 Σ_{α>0} Σ_{k≥1} (μ+kα, α) m(μ+kα)`, base `m(λ)=1`.
  Computed layer-by-layer (descending by level) over the weights generated by subtracting simple roots; the inner `k`-sum stops when `μ+kα` leaves the weight system. Use the generate-all-weights variant first (simplest, matches Sage); optimize to dominant-only + orbits if needed.
- **Weight system / Weyl orbits:** simple reflection `sᵢ(μ) = μ − ⟨μ,αᵢ^∨⟩ αᵢ`; orbit BFS with Snow's descent-only dedup (reflect at node `i` only when the `i`-th Dynkin label is positive). Multiplicities are Weyl-invariant.
- **Casimir:** `CasimirEigenvalue = (λ, λ+2ρ)` with the `C_n` form-halving above.
- **Self-check baked into tests:** `RepresentationDimension == Σ_orbits (orbit size × multiplicity)`; integrality asserts in Freudenthal (`Mod[2·accum, denom]==0`).

## 5. Layer 2 — the matrix engine (`Kernel/Representations.wl`)

Abstract highest-weight construction (de Graaf / GAP `HighestWeightModule`), driven only by the **Cartan matrix**, **Dynkin labels**, and the **Layer-1 multiplicities** — no tensor embedding, so spinors are reached uniformly.

**Algorithm.**
1. **Highest-weight vector** `v_λ`: `eᵢ v_λ = 0`, `hᵢ v_λ = λᵢ v_λ`.
2. **Build weight-space bases by BFS in level** (number of `f`'s applied). For each accepted weight-`μ` vector `u` and simple `i`, the candidate `fᵢ·u` has weight `ν = μ−αᵢ`. For each target weight `ν`, accumulate candidates from **all** sources `(u,i)` reaching it and keep a maximal independent subset of size `m(ν)` (the known multiplicity); record each `fᵢ·u`'s coordinates in that chosen basis.
3. **Linear dependence via the Shapovalov (contravariant) form.** The form satisfies `⟨fᵢ u, w⟩ = ⟨u, eᵢ w⟩`, `⟨v_λ,v_λ⟩=1`, weight spaces of different weights orthogonal. Compute `⟨w, w′⟩` of two `f`-words by the recursion: push `eᵢ` to the right using `eᵢ fⱼ = fⱼ eᵢ + δ_ij hᵢ`, with `eᵢ v_λ = 0` and `hᵢ` acting as the (known) Dynkin label of the current weight. The **rank of the per-weight Gram block equals the weight multiplicity**, so a pivoted Gram–Schmidt / LDLᵀ on it simultaneously discards dependent (and Serre-vanishing) words and orthonormalizes — no separate Serre implementation needed.
4. **Assemble matrices** in the weight-ordered orthonormal basis:
   - `Hᵢ` = diagonal of Dynkin label `i` of each basis vector's weight.
   - `Fᵢ` = coordinates of `fᵢ·(basis vector)` in the lower weight space (read off step 2–3).
   - `Eᵢ = ConjugateTranspose[Fᵢ]` (forced by adjointness in the orthonormal basis).
5. **Memoize** the built module per `(g, λ)`.

**Exactness:** Gram entries are rational; orthonormalization introduces `Sqrt` of rationals (kept symbolic). `"Normalized"→False` keeps everything rational (unnormalized basis, diagonal rational metric).

**Feasibility:** cost ~ `dim V(λ)` and the largest weight multiplicity (Gram-block size). Small/fundamental/adjoint reps of A/B/C/D up to moderate rank are routine exactly; document practical limits.

## 6. Module structure & tests

```
Kernel/Weights.wl           Layer 1: dimension, Freudenthal, Weyl orbits, Casimir, reflections, Dynkin↔Euclidean
Kernel/Representations.wl   Irrep object + Shapovalov engine + RepresentationMatrices/HighestWeight
Tests/Weights.wlt           dims, multiplicities, weight-system sum = dim, Casimir
Tests/Representations.wlt   per-irrep: [Eᵢ,Fⱼ]=δ_ij Hᵢ, Hᵢ diagonal = Dynkin labels, dim, spinor cases, defining-rep match
```
Main file `Kernel/ClassicalLieAlgebra.wl` declares the new public symbols/usages and `Get`s the two new subfiles (before the `Protect`).

## 7. Validation / testing strategy

- **Known dimensions:** `Irrep[SU[3],{1,1}]`→8, `{1,0}`→3; `Irrep[SO[5],{1,0}]`→5 (vector), `{0,1}`→4 (**spinor**); `Irrep[Sp[4],{1,0}]`→4, `{0,1}`→5; adjoints → `LieAlgebraDimension[g]`.
- **Casimir:** adjoint → `2 h^∨` (e.g. su(3) adjoint → 6 in long-root²=2 units); fundamental of su(n) → `(n²−1)/n`.
- **Matrix consistency (every tested irrep):** `[Eᵢ,Fⱼ] == δ_ij Hᵢ`; `[Hᵢ,Eⱼ] == a_ji Eⱼ` (Cartan-matrix row); `Hᵢ` diagonal with entries = Dynkin label `i` of each weight; matrices honor the weight grading.
- **Tie to Phase 1:** the fundamental irrep's `RepresentationMatrices` equals `Generators[g,"Chevalley"]` from Phase 1 up to basis ordering/permutation (assert via a similarity transform or by matching `H` spectra + commutators).
- **Spinor must work:** explicit `SO[5]` spinor `{0,1}` (4-dim) built and checked — this is the case the tableau engine could not do.
- **External oracle:** spot-check a few irreps' Casimirs/commutators against **GroupMath**; use **LieART** Dynkin-label conventions for naming.

## 8. Implementation phasing (within Phase 2)

1. `Kernel/Weights.wl`: Dynkin↔Euclidean, `ρ`, Weyl reflections + orbits, `RepresentationDimension`, `CasimirEigenvalue` (+ C_n halving). Tests: known dims/Casimirs.
2. Freudenthal `WeightSystem` (generate-all variant); test multiplicities + `dim == Σ orbit·mult`.
3. `Irrep[g, λ]` object: validation, `HighestWeight`, display; wire combinatorial accessors to it.
4. Shapovalov form recursion (`⟨word, word⟩`) + the `eᵢ`-past-`f`-words reduction; unit-test on su(2)/su(3) Gram matrices.
5. Weight-basis BFS + Gram-rank capping → `Fᵢ`, `Hᵢ`; then `Eᵢ = Fᵢ^†`. Validate su(2) spin-j, su(3) fundamental + **adjoint (degenerate 0-weight space)**.
6. Extend/verify so(5) vector, **so(5) spinor**, sp(4); add the Phase-1 defining-rep match and `[E,F]=H` checks; GroupMath spot-checks.
7. Docs: usage messages; README "Representations" section with a worked `Irrep` example.

## 9. Decisions for review

1. **`RepresentationMatrices` default basis:** orthonormal (`Eᵢ=Fᵢ^†`, surds) — proposed default; `"Normalized"→False` for exact-rational. Confirm default.
2. **`WeightSystem` weight coordinates:** Dynkin labels (proposed, physics-standard) vs Euclidean. Proposed Dynkin.
3. **Symbol names:** `Irrep`, `RepresentationDimension`, `WeightSystem`, `CasimirEigenvalue`, `RepresentationMatrices`, `HighestWeight` — verify vs `System`` and rename clashes. Proposed names as listed.
4. **Scope guard:** keep tensor products / branching / GT fast-path / exceptional algebras out of this cycle. Proposed out.
